## Release focus

Making the evidence actually leave the building. Loom's ingest, hashing, and review layers were solid, but the moment evidence had to become a production — served on opposing counsel, attached to a declaration, handed to chambers — the workflow broke. Exports silently ignored every option you set and never contained a single original file. Nothing could attach an asset to a timeline event, so the product's central claim (every claim traces to source material) could not be exercised in the interface at all. This release closes that gap and fixes four bugs found along the way, two of which were making features quietly return nothing.

## Highlights

- **Exports honor what you asked for, and say what they contain.** Export options were dropped on the floor: the wizard's date range, event and asset selection, and "include original files" had no effect on the artifact, and the report builder's section toggles and executive summary never reached the API. They all work now. `include_originals` genuinely ships the original media, and each file is re-read and re-hashed against its intake digest **at export time** — a mismatch aborts the export rather than shipping corrupt evidence. Every bundle's manifest and README now state what was included and what was excluded, and why.
- **A pre-filled declaration you can sign.** Court bundles now carry a 28 U.S.C. § 1746 declaration with the FRE 902(13)/(14) elements filled in from real data: software version, the hashing and verification process, and a per-exhibit table of the SHA-256 recorded at intake plus the export-time verification result and timestamp. The declarant block is deliberately blank for counsel to review and execute. The custody claim is scoped to *within this system since ingest* and says so explicitly — it makes no representation about a file's creation or its handling before intake.
- **Opposing counsel can verify a bundle without installing anything.** Every court bundle ships `verify.html`, which re-hashes the files you select against `MANIFEST.sha256` in a browser with no install and no network, and `verify.py`, which does the same from a shell using only the Python standard library. An attestation the other side cannot check invites the argument that you are hiding behind proprietary math.
- **A work-product firewall on exports.** Timeline events, evidence links, conflict resolutions, and annotations are attorney work product (FRCP 26(b)(3)). The export wizard now presents the evidence layer and the analysis layer as separate choices; court bundles default to an evidence-only production, and including the analysis layer stamps ATTORNEY WORK PRODUCT on the rendered report.
- **Evidence linking works in the interface.** You can attach an asset to a timeline event with an explicit `supports` / `contradicts` / `context` relationship and a clip range, unlink it, and edit the event — from the timeline drawer or straight from the review workspace, where the clip range prefills from the player's in/out marks. Accepting a proposed cluster now links its source assets automatically instead of creating an event with no sources.
- **Litigation hold.** A case under hold refuses purge and asset deletion, requires a reason to set or release, audits both, and shows a persistent banner. Case destruction leaves a permanent hash-verified tombstone of what was destroyed; during pending or anticipated litigation that artifact cuts against the party holding it (FRCP 37(e)), so destruction now needs a lock, not just a confirmation dialog.
- **One-click integrity verification.** Verify a whole case or a single asset from the interface, see when each asset was last proven intact, and download a dated integrity report. Custody entries now read as statements a witness can say out loud ("Integrity verified — hashes match") rather than raw action slugs.

## Fixes

- **Capture times were never recorded.** Ingest extracted each file's container creation time into a metadata blob but never wrote it to the `capture_time` column, so clustering, correlation, the map, and court-bundle exhibit ordering were all filtering on a column that was always empty in production. Existing assets are backfilled from the metadata they already carry.
- **Case purge aborted on server deployments.** The append-only trigger protecting the custody log also fires on the cascade deletes purge relies on, so purging a case failed on Postgres. The only test covered SQLite, where the trigger does not exist. Purge now passes the guard for exactly that operation and nothing else, and a Postgres test covers it.
- **The integrity report returned a server error on every real asset.** Its schema only accepted string values in custody details, while verification, ingest, and bundle import all write booleans and lists. It was invisible because the tests mocked the service out. That endpoint also used to run a full re-verification on a read — a viewer-role request that quietly mutated evidence state; reads are now read-only.
- **Setting an event status failed.** The API accepted a vocabulary the database rejected, so any status other than "draft" hit a constraint violation. Imported bundles could also carry a foreign status and abort the whole import. One vocabulary now, enforced end to end and carried into the API schema.
- Dependabot auto-merge had been failing on every pull request; the release script now performs the main→dev reconcile that, when skipped by hand, silently starved a release PR of CI (#391); the security scanner is pinned to a release instead of a moving branch; and SQLite foreign keys are enforced on the workflows engine, not just the API engine.

## Migrations

- **019** — export options, per-asset verification recency, and case litigation-hold columns.
- **020** — aligns the timeline status constraint with the model vocabulary (coerces any out-of-vocabulary rows to `draft` first).
- **021** — backfills `assets.capture_time` from already-stored metadata, in batches, filling only empty values.
- **022** — gates the append-only custody trigger so a case purge can complete on Postgres (no-op on Desktop Lite).

All four replay safely on Desktop Lite databases whose schema is newer than their recorded stamp.

## Install

- **Desktop Lite (individuals):** update in place from the in-app updater, or download the installer from this release's assets and verify against `SHA256SUMS`. Your data directory is preserved; the migrations run on first launch.
- **Server (organizations):** run `alembic upgrade head`. Migration 022 changes a trigger function in place. See [`docs/prod-deploy.md`](docs/prod-deploy.md).

## Known limitations in 0.3.0

- **No redaction interface.** The backend can blur, black-box, and pixelate images, but there is no UI, and video and audio redaction do not exist. Protest footage is full of uninvolved third parties; until this ships, redaction must happen outside Loom.
- **Machine transcripts are not marked as drafts.** Speech-to-text output has no verified/unverified state, so an unreviewed transcript looks the same as a checked one. Treat transcripts as finding aids, not as a record.
- **Custody begins at ingest.** There are no fields for who handed you a file, when, or on what device. That gap is where authentication fights usually happen; record it outside Loom for now.
- **Exhibit numbers are not persisted.** They are computed per court-bundle render, so they are stable for a given case but are not stored, displayed in the app, or stamped onto produced files. No Bates numbering.
- **Viewing evidence leaves no trace,** by design for now: a log of which clips an attorney watched is a discoverable map of trial preparation. A per-case, off-by-default access log is the intended shape if it lands.
- **Installers remain OS-unsigned by decision** (see v0.2.6 notes); the backend port is fixed at 8000 (#354); Windows OCR needs a manual tesseract install; diarization is server-profile only; the macOS Intel installer is not produced.

## Security

- Exports gained a deliberate egress path: original evidence files can now leave the machine inside a bundle. That happens only when explicitly requested, every file is re-verified on the way out, and each one is recorded in the asset's chain of custody as `exported`.
- The work-product firewall reduces the chance of disclosing analysis material by default; the analysis layer is excluded from court bundles unless it is explicitly opted in.
- A viewer-role read no longer mutates evidence state, and the shipped bundle verifiers make no network requests.
- Release artifacts remain verifiable via `SHA256SUMS`, and the in-app updater continues to verify every update against the minisign public key pinned in the app before installing.
- Report vulnerabilities privately by emailing the maintainer — do not open a public issue.
