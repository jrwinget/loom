## Release focus

Desktop startup you can trust. A field report of a fresh Ubuntu install that could never reach login drove a hardening pass over the entire boot chain: the health probe now tells the truth when the database is down, slow first launches show live progress instead of dying at an arbitrary 60-second wall, a stale process squatting on the backend port is named instead of guessed at, a corrupted secrets file heals itself instead of bricking the install forever, and the one migration path CI never exercised — the upgrade an existing install runs after every update — is now smoke-tested on every build, from the installed package.

## Highlights

- **Honest health probe.** `/api/v1/health` now answers 503 when any dependency check fails instead of hiding the failure in a 200 body. The desktop shell no longer declares a database-dead backend "ready", and the server-profile docker healthcheck and alerting finally behave as their documentation always claimed.
- **Slow launches show progress.** The startup budget is now a 180-second ceiling with once-a-second progress events: after ten seconds the boot panel shows elapsed time and explains that a first launch can take a few minutes. A backend that is up but unhealthy fails fast with the failing service named, rather than burning the whole deadline.
- **Port conflicts are named.** Both the shell and the sidecar detect a process already holding 127.0.0.1:8000 before doing any work, and say so — including what to do about it — instead of surfacing a bind traceback after the schema bootstrap already ran.
- **Corrupt secrets self-heal.** The bootstrap secrets file deliberately survives factory reset and data-dir deletion, which meant a corrupted file bricked boot with no user-reachable remedy. An unreadable store is now backed up and regenerated, and invalid values are rotated — the cost is one forced re-login.
- **The error panel helps.** When the backend does fail, the panel now lists the exact log directories for your platform and offers the one-click diagnostics export that previously only lived in Settings.
- **Upgrade path under test.** The CI smoke now boots every built sidecar twice: once against a fresh directory, and once against a database whose migration stamp is wound back a release — the exact path every existing install takes after an update, and the path that broke in this release cycle (migration 018 crashed when its index already existed; now idempotent and regression-tested). On Linux the smoke also runs against the sidecar installed from the actual .deb, not just the build output.
- **CI resilience.** Dependabot and fork PRs no longer fail the desktop build for lack of the updater signing key (they build unsigned installers; tag builds hard-require the key up front), the desktop shell's Rust unit tests run in CI for the first time, and the security audits survived npm's retirement of its legacy audit endpoints.
- **Dependencies.** uvicorn ≥0.51 (validated against the frozen sidecar on all three platforms), plus routine backend and frontend minor updates. The av 18 and opencv 5 majors are deliberately held behind dedicated migration issues (#352, #353) — both carry PyInstaller packaging risk that needs validation on the frozen binary, not just a green build.

## Migrations

- No new migrations. Migration 018 (from v0.2.3) is now idempotent so it can never crash a boot against a schema that already carries its index.

## Install

- **Desktop Lite (individuals):** update in place from the in-app updater, or download the installer from this release's assets. No factory reset required.
- **Server (organizations):** see [`docs/prod-deploy.md`](docs/prod-deploy.md). Note the `/api/v1/health` status-code change if you probe it: 200 = ready, 503 = alive but degraded (body names the failing service), connection refused = down.

## Known limitations in 0.2.4

- **macOS and Windows installers are unsigned.** Gatekeeper requires right-click-Open on macOS; SmartScreen warns on Windows. The CI wiring for signing exists and activates when certificates are configured (#349, #350).
- **The backend port is fixed at 8000.** A conflict is now detected and explained, but not avoided; dynamic port allocation is tracked in #354.
- **Cold first launch can still take minutes on slow disks.** The onefile sidecar self-extracts on every start; the structural fix (onedir packaging) is the theme of the next release (#357).
- **Windows OCR still needs a manual tesseract install; diarization remains server-profile only; Gemini transcription returns prose, not timed segments; macOS Intel installer is not produced.** Carryovers from prior releases.

## Security

- `click` 8.4.2 and `pillow` 12.3.0 clear all currently published advisories; the remaining `setuptools` advisory cannot resolve while torch pins `setuptools<82` and is documented in the audit ignore list (it only affects sdist packing from untrusted manifests, which nothing here does).
- Secrets regenerated by the self-heal path only ever sign JWTs and presigned URLs — rotation forces a re-login and expires in-flight download links; nothing at rest is encrypted with them.
- Report vulnerabilities privately by emailing the maintainer — do not open a public issue.
