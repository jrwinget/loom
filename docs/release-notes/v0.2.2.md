## Release focus

Evidence can now leave one Loom and arrive whole in another, without losing its chain of custody. A new **portable bundle** carries a complete case — originals, timeline, annotations, transcripts, and the full custody trail — as a streamed, hash-manifested, optionally signed archive; importing it recreates the case with fresh identifiers, every original's hash preserved and re-verified, and the source deploy's custody chain embedded so nothing is severed. Around that: cases can finally be **archived and purged** (with an audit tombstone written before anything is destroyed), two-factor auth gains **recovery-code regeneration** and — closing a real gap — now requires your **password** to disable, and the release process itself is scripted so its recurring footguns can't come back.

## Highlights

- **Portable bundle export.** A superset of the court bundle aimed at another Loom install rather than a judge: `data/*.json` full rows, the original evidence files, a `MANIFEST.sha256` over every entry, and an optional detached Ed25519 signature. The archive is streamed to disk — originals are copied through in chunks and never held in memory at once — so a case with tens of gigabytes of footage exports without exhausting RAM.
- **Bundle import.** `POST /api/v1/imports/bundle` streams the archive in, rejects a **tampered** bundle (every manifest entry is re-hashed) or a **duplicate** (matched on the bundle's sha256) before creating anything, then recreates the case as a background job: new UUIDs throughout, every original's content hash preserved and re-verified on the way into WORM storage, and one `imported` custody entry per asset embedding the source deploy's full custody chain plus the signature-verification status. A bundle signed by a key you trust imports as verified; one signed by an unknown key still imports, with the unverified source recorded rather than hidden. The import UI lives on the Cases page and reports verification status plainly.
- **Case lifecycle: archive and purge.** A case can be archived, and a closed or archived case can be purged by its owner through a typed-confirmation dialog. An append-only audit tombstone — title, reason, and every asset's hash — is committed **before** any row or file is deleted, so the record of what was destroyed always outlives the destruction.
- **Two-factor auth completeness.** Recovery codes can be regenerated (confirmed with a live authenticator code; the previous set stops working). **Security fix:** disabling MFA now requires your account password — the previous endpoint accepted only an authenticator code, which meant a stolen session could remove the second factor. The security settings page is rebuilt around the full enroll / regenerate / disable story.
- **Release automation.** `scripts/cut-release.sh` scripts the two-step cut (prepare → PR to `main` → tag), regenerating the version-embedding API contract and refusing to proceed without release notes; a CI guard refuses to build a tag whose release page already carries assets. This release is the first cut with it.

## Known limitations in 0.2.2

- **Bundle signature trust is configuration-driven.** Imports verify against the Ed25519 public keys in `LOOM_BUNDLE_VERIFY_PUBLIC_KEYS`; with none configured, every signed bundle imports as "unverified" (still recorded in custody). There is no key-exchange UI yet.
- **A purged case's background-job artifacts are reaped best-effort.** If storage reclamation fails after the audit tombstone and rows are committed, an orphaned original may remain for later cleanup — deliberately, so a storage error can never destroy an original with no surviving record.
- **Windows OCR still needs a manual tesseract install; diarization remains server-profile only.** Carryover from v0.2.1.
- **The Gemini cloud transcription path returns prose, not timed segments.** Carryover from v0.1.17.
- **macOS Intel installer is not produced** (Apple Silicon only). Carryover from v0.1.1.

## Security

- Portable bundles are tamper-evident (per-entry SHA-256 in a signed manifest; import hard-fails on any mismatch) and idempotent (duplicate imports are refused). Signature verification is explicit about trust: an unknown signer is imported-but-flagged, never silently accepted.
- Disabling two-factor authentication now requires the account password, closing a stolen-session escalation path.
- Case purge writes its audit tombstone before deletion and is owner-only, gated behind a closed/archived state and a typed-title confirmation.
- Report vulnerabilities privately by emailing the maintainer — do not open a public issue.
