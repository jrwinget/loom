Seventeenth beta release of Loom — an evidence operating system for civil-rights legal teams that turns mixed field evidence (video, photos, audio, FOIA returns) into a defensible event timeline where every claim traces back to source material. Civil-liberties tooling: no face recognition, no suspicion scoring, no automated identity resolution.

> **Beta scope:** prepared for first use in Illinois (state and federal § 1983 actions). Defaults are documented in [`docs/requirements.md`](docs/requirements.md) and are jurisdiction-tunable.
>
> **Not legal advice.** Statutes and rules of evidence are referenced for design context only. Admissibility, consent, retention, and disclosure decisions for any specific matter belong with licensed counsel.

## Release focus

This release is about honesty and visibility. The desktop app no longer pretends: missing processing engines used to produce fabricated transcript rows and silently empty OCR/scene results — they now fail loudly with a user-actionable remedy, and a capabilities check disables what an install genuinely cannot do. Long-running work is finally visible: a jobs bell shows per-stage progress, completion and failure toasts carry the real backend error, and failed jobs can be retried in place. Ingest sheds its 100 MB ceiling with a streaming upload path sized for field footage. And the app watches itself: generated API types fail CI on contract drift, a schema-parity guard keeps the desktop and server databases provably identical, and the first end-to-end browser test suite already paid for itself by catching three shipped bugs.

## Highlights

- **Fail-loud processing engines (`backend/src/loom/services/engines.py`).** Missing transcription/OCR/scene-detection/media tooling now raises `EngineUnavailableError` with a remedy string instead of fabricating placeholder results — for an evidence product, a fabricated row is worse than an error. Failures land in `assets.processing_error` (migration 014) and in the job status the UI shows.
- **Capabilities endpoint + honest UI gating (`GET /api/v1/capabilities`).** The frontend disables Transcribe/OCR/Detect-scenes buttons with remedy tooltips when an engine is unavailable; speaker labels are labeled server-profile-only.
- **Streaming ingest (`POST /cases/{id}/assets/upload-stream`).** Uploads stream to disk with incremental hashing and an atomic move into WORM storage — no more whole-file buffering in memory and no more 100 MB cap on the desktop (the shell passes an uncapped limit; disk is the boundary). Content-Length prechecks reject oversized uploads before any bytes move.
- **Jobs bell and live progress.** Transcription, scene detection, exports, URL ingest, and upload processing all register in a header jobs menu with per-stage progress on the desktop (steps from the lite runner), completion/failure toasts that surface the backend's actual error message, retry for failed jobs, and automatic refresh of the affected screens.
- **Dark mode.** Light/dark/system toggle in the header, `color-scheme`-aware chrome, and a full sweep of the raw-palette stragglers including map controls and status badges.
- **Dashboard v1.** Recent cases, active jobs, storage advisory, recent case activity, and quick actions replace the placeholder landing page.
- **Contract drift now fails CI.** The backend exports its OpenAPI schema deterministically; generated TypeScript types are checked in with a CI job that fails when a schema change lands without regeneration, plus compile-time assertions that the load-bearing hand-written types match the camelized wire shapes. This targets the exact drift class behind the v0.1.13 crashes.
- **Schema parity guard.** CI proves the SQLAlchemy models (the desktop's schema source) and the alembic migrations (the server's) describe the same database (migration 015 reconciled the historical drift). The desktop and server profiles can no longer diverge silently.
- **First end-to-end test suite (Playwright).** One continuous journey — first-run onboarding, MFA enrollment and challenge, case creation, streaming upload, timeline event, export — drives the real UI against a real lite backend in CI.
- **Export downloads fixed.** The export list's Download button fetches a presigned URL instead of linking a raw storage key (which 404'd on the server profile).

## Fixes the E2E suite caught before they were reported

- **First-run recovery codes were skipped.** A redirect race sent the operator to the dashboard before the "save your recovery codes" step — the only time those codes exist in plaintext, and the only credential-recovery path on a single-admin desktop install.
- **MFA challenge success stranded users on the login page.** Completing the two-factor challenge authenticated the session but never navigated, re-rendering the sign-in form as if login had failed.
- **Audit trail dropped every collection-level entry.** Login attempts, MFA enrollment, and case creation never reached the append-only audit log (a NOT NULL constraint rejected them; the failure was downgraded to a warning). Migration 016 fixes the constraint; these events are recorded from now on.

## Migrations

- **014, 015, 016** (`assets.processing_error`; schema-parity reconciliation; nullable `audit_log.resource_id`). Server deploys: `alembic upgrade head` as usual.
- **Desktop installs now migrate themselves.** Previously a lite database was frozen at the schema of the release that created it; the sidecar now replays pending migrations at boot. Upgrading from any earlier beta requires no factory reset.

## Install

- **Desktop Lite (individuals):** download the installer for your platform from this release's assets, or follow [`docs/desktop-lite.md`](docs/desktop-lite.md) to build from source. No factory reset required.
- **Server (organizations):** see [`docs/prod-deploy.md`](docs/prod-deploy.md); run `alembic upgrade head`.

## Known limitations in 0.2.0

- **On-device AI on the desktop is still pending.** Local transcription/OCR/scene-detection engines and bundled `ffmpeg`/`tesseract` are the next milestone; until then the capabilities screen states plainly what's unavailable and why, and desktop transcription requires the opt-in cloud path. Carryover from v0.1.16.
- **The Gemini path returns prose, not timed segments**, and inlines the file (~15 MB cap). Carryover from v0.1.17.
- **AppImage video codecs are bundled at build time** — verify playback on a clean host. Carryover from v0.1.17.
- **Three breaking-major frontend upgrades held for dedicated migration:** Vite 8, Tailwind CSS 4, ESLint 10. Carryover from v0.1.13.
- **macOS Intel installer is still not produced** (Apple Silicon only). Carryover from v0.1.1.
- **Desktop sidecar cold-start on Windows can still take 15–25 s.** Carryover from v0.1.3.

## Security

- The audit trail now actually records authentication events (see Fixes) — entries were dropped, never mis-recorded, and the log remains append-only.
- Streaming uploads validate magic bytes on the first 8 KB and enforce the size cap mid-stream; temp files live on the same filesystem as the WORM store so finalization is an atomic rename, and stale temp files are reaped on startup.
- Dependency advisories for `msgpack` and `pydantic-settings` were resolved by floor bumps. Documented suppressions are unchanged (torch CVE, local-only; the temporalio-vendored pyo3 advisory in `.trivyignore`).
- Desktop Lite still makes no outbound connection unless the user submits a URL or has enabled cloud transcription.
- Report vulnerabilities privately by emailing the maintainer — do not open a public issue.
