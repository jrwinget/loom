## Release focus

Instant backend start. The bundled backend no longer self-extracts a multi-hundred-megabyte payload on every launch: it now ships as a ready-to-run directory tree inside the app. Cold start drops from tens of seconds (minutes on slow disks) to a few seconds, antivirus software no longer rescans the whole payload at each launch, and the failure class where a locked-down or full temp directory prevented the app from ever starting is gone outright. This is the structural fix behind v0.2.4's startup-resilience work — the compensating timeouts and progress reporting from that release remain, they just should not be needed anymore.

## Highlights

- **No more per-launch self-extraction.** The backend ships as a PyInstaller onedir tree bundled with the app (Linux: `/usr/lib/Loom/loom-backend/`; macOS: inside the app bundle; Windows: the install directory). Launch goes straight to serving — no unpack step, no temp-directory dependency, no repeated antivirus sweeps of the payload.
- **CI validates the packaging shape.** Every build asserts the installed layout inside the deb (launcher executable bit, bundled migration data) before boot-testing the tree both from the build output and from an actual package install, on tag builds included.
- **Size trade, stated plainly.** Installer downloads are essentially unchanged (the payload was always inside them); installed disk footprint for the backend component grows because the tree is no longer compressed on disk — the price of instant starts. Exact per-platform numbers are in the release assets' build logs.

## Install

- **Desktop Lite (individuals):** update in place from the in-app updater, or download the installer from this release's assets. No factory reset required. Your data directory and settings are untouched by the packaging change.
- **Server (organizations):** no changes; see [`docs/prod-deploy.md`](docs/prod-deploy.md).

## Known limitations in 0.2.5

- **macOS and Windows installers are unsigned.** Gatekeeper requires right-click-Open on macOS; SmartScreen warns on Windows. Signing activates when certificates are configured (#349, #350) — note the onedir tree adds per-file signing work, tracked on #349.
- **The backend port is fixed at 8000** (conflict detection shipped in v0.2.4; dynamic allocation is #354).
- **Windows OCR still needs a manual tesseract install; diarization remains server-profile only; Gemini transcription returns prose, not timed segments; macOS Intel installer is not produced.** Carryovers from prior releases.

## Security

- The packaging change moves no trust boundaries: the same binaries run from a bundled directory instead of a temp-dir extraction, the updater signature scheme is unchanged, and dropping the temp-directory dependency removes a writable-then-executed path from the launch sequence.
- Report vulnerabilities privately by emailing the maintainer — do not open a public issue.
