## Release focus

Fixing the update crash-loop that locked long-time desktop installs out of the app. A database created on v0.1.4–v0.1.15 and updated through v0.1.16+ carried a schema newer than its recorded migration stamp; the upgrade step added in v0.2.0 then replayed a migration onto a table that already existed and the backend died before it could serve a single request — every launch, every retry. This release makes those replays safe, so affected installs heal themselves on first launch after updating.

## Highlights

- **Stuck installs recover automatically.** If your app has been showing "Loom backend did not start" with a `table app_settings already exists` error, updating to v0.2.7 is the complete fix: the pending migrations replay cleanly, the stamp catches up, and all your data is untouched. No factory reset, no manual database surgery.
- **The whole class of bug is closed, not just this instance.** Migrations 013, 014, and 017 gained the same replay guards migration 018 already had, covering every migration a released build could replay onto an existing schema. Migration 016 now skips a pointless full rebuild of the audit table during replay.
- **CI now catches the next one before it ships.** The sidecar smoke test replays the entire migration range from the oldest stamp any real install carries (012), so a future migration that isn't replay-safe fails its own pull request instead of a user's laptop.

## Migrations

- No new migrations. Migrations 013–017 gained replay guards; databases stuck in the update crash-loop complete their upgrade automatically on next launch.

## Install

- **Desktop Lite (individuals):** update in place from the in-app updater, or download the installer from this release's assets and verify against `SHA256SUMS`. If your install is currently stuck on the backend error screen, the in-app updater may be unreachable — download the installer directly; your data directory is preserved.
- **Server (organizations):** no changes; the guards are no-ops on the sequential Postgres migration path. See [`docs/prod-deploy.md`](docs/prod-deploy.md).

## Known limitations in 0.2.7

- **Installers remain OS-unsigned by decision** (see v0.2.6 notes). Gatekeeper needs the one-time right-click-Open; SmartScreen needs More info → Run anyway.
- **The backend port is fixed at 8000** (conflict detection shipped in v0.2.4; dynamic allocation is #354).
- **Windows OCR still needs a manual tesseract install; diarization remains server-profile only; Gemini transcription returns prose, not timed segments; macOS Intel installer is not produced.** Carryovers from prior releases.

## Security

- No trust boundary changed: the fix touches only how already-shipped schema migrations behave when re-applied to a database that already carries their objects.
- Release artifacts remain verifiable via `SHA256SUMS`, and the in-app updater continues to verify every update against the minisign public key pinned in the app before installing.
- Report vulnerabilities privately by emailing the maintainer — do not open a public issue.
