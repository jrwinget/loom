## Release focus

Download verification and unsigned-build transparency. Loom is community-built open-source software and deliberately does not purchase the paid Apple/Microsoft code-signing subscriptions that suppress install-time warnings — this release makes that fact visible, explained, and verifiable everywhere users actually meet it, instead of leaving SmartScreen and Gatekeeper prompts to speak for themselves.

## Highlights

- **`SHA256SUMS` on every release.** Starting with this release, the release page carries a checksum file for every installer, generated by CI from the exact artifacts it built. `docs/desktop-lite.md` shows the one-line verify command per platform.
- **The warnings are explained where they happen.** The README install steps, the desktop guide, the first-run welcome screen, and the in-app update banner each carry a short plain-language note: the OS prompts mean "publisher unknown to Apple/Microsoft" — the expected notice for community software without paid certificates — and point at the two real verification mechanisms: release checksums, and in-app updates that install only after verifying against Loom's own signing key pinned inside the app.
- **The decision is recorded.** The operations runbook documents that OS code signing is deliberately unfunded, and the CI signing steps remain dormant behind secrets so future funding can reactivate them without engineering work.

## Install

- **Desktop Lite (individuals):** update in place from the in-app updater, or download the installer from this release's assets — and, from now on, check it against `SHA256SUMS` if you want byte-level certainty. No factory reset required.
- **Server (organizations):** no changes; see [`docs/prod-deploy.md`](docs/prod-deploy.md).

## Known limitations in 0.2.6

- **Installers remain OS-unsigned by decision** (see above). Gatekeeper needs the one-time right-click-Open; SmartScreen needs More info → Run anyway. The env-gated CI signing steps stay in place should funding ever change the picture.
- **The backend port is fixed at 8000** (conflict detection shipped in v0.2.4; dynamic allocation is #354).
- **Windows OCR still needs a manual tesseract install; diarization remains server-profile only; Gemini transcription returns prose, not timed segments; macOS Intel installer is not produced.** Carryovers from prior releases.

## Security

- Release artifacts are now independently verifiable: `SHA256SUMS` is produced in CI from the same artifacts the release attaches, and the in-app updater continues to verify every update against the minisign public key pinned in the app before installing.
- No trust boundary changed: the notices are informational, and the absence of OS code signatures is a funding posture, not a change in how artifacts are built or delivered.
- Report vulnerabilities privately by emailing the maintainer — do not open a public issue.
